Requisições com XMLHttpRequest (XHR)

Como o navegador busca ou envia dados a um servidor sem recarregar a página inteira.

O que é XHR?

XMLHttpRequest é a API clássica do JavaScript para fazer requisições HTTP de forma assíncrona: o script continua rodando enquanto espera a resposta do servidor (por exemplo, uma API REST).

Apesar do nome mencionar XML, hoje o mais comum é trocar JSON com APIs modernas. O fluxo básico é sempre o mesmo: criar o objeto, configurar, enviar e tratar o retorno em callbacks ou eventos.

Passo a passo

  1. new XMLHttpRequest() — cria a instância
  2. open(método, url, async) — define GET/POST, URL e se é assíncrono
  3. setRequestHeader() — opcional (tipo do corpo, token, etc.)
  4. send(corpo) — dispara a requisição
  5. Escutar onload / onerror ou onreadystatechange — ler a resposta

GET — buscar dados

const xhr = new XMLHttpRequest();

xhr.open("GET", "https://api.exemplo.com/usuarios/1", true);

xhr.onload = function () {
  if (xhr.status >= 200 && xhr.status < 300) {
    const dados = JSON.parse(xhr.responseText);
    console.log(dados);
  } else {
    console.error("Erro HTTP:", xhr.status);
  }
};

xhr.onerror = function () {
  console.error("Falha de rede ou CORS");
};

xhr.send(); // GET não envia corpo

xhr.responseText traz o corpo da resposta como string. Se for JSON, use JSON.parse().

POST — enviar dados

const xhr = new XMLHttpRequest();
const payload = JSON.stringify({ nome: "Ana", email: "ana@email.com" });

xhr.open("POST", "https://api.exemplo.com/usuarios", true);
xhr.setRequestHeader("Content-Type", "application/json");

xhr.onload = function () {
  if (xhr.status >= 200 && xhr.status < 300) {
    console.log("Criado:", JSON.parse(xhr.responseText));
  }
};

xhr.send(payload); // corpo vai no send()

Em POST/PUT/PATCH, o corpo costuma ser JSON; o header Content-Type: application/json avisa o servidor como interpretar.

readyState e status

Com onreadystatechange, você acompanha cada etapa da requisição. O valor útil para ler a resposta é readyState === 4 (concluída). 

xhr.onreadystatechange = function () {
  if (xhr.readyState === 4) {
  // 0 UNSENT → 1 OPENED → 2 HEADERS → 3 LOADING → 4 DONE
    console.log("Status:", xhr.status);
    console.log("Resposta:", xhr.responseText);
  }
};
  • 2xx — sucesso (ex.: 200 OK, 201 Created)
  • 4xx — erro do cliente (404 não encontrado, 401 não autorizado)
  • 5xx — erro do servidor

Outros métodos HTTP

O primeiro argumento de open() aceita o verbo HTTP: GET, POST, PUT, PATCH, DELETE, etc. A diferença está no que você envia em send() e no que a API espera receber. 

xhr.open("DELETE", "https://api.exemplo.com/usuarios/42", true);
xhr.send();

CORS e ambiente de teste

CORS: o navegador só deixa seu JavaScript ler a resposta se o servidor permitir a origem da sua página (cabeçalho Access-Control-Allow-Origin). APIs públicas de estudo, como JSONPlaceholder, já liberam isso. Abrir o HTML direto como file:// às vezes complica testes — prefira Live Server ou um servidor local.

Resumo

  • XHR comunica o front-end com APIs/servidores de forma assíncrona.
  • open + send definem método, URL e corpo.
  • Trate sucesso pelo status e parseie responseText quando for JSON.
  • Use onerror para falhas de rede; verifique CORS se a resposta não chegar.
Hoje em dia: muitos projetos usam fetch() ou bibliotecas como Axios, que retornam Promises. O modelo mental do XHR (requisição → resposta → status) continua válido para entender qualquer cliente HTTP no front-end.
