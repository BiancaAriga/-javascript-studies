Promises e XHR

Como usar Promises para organizar requisições XHR e encadear o tratamento assíncrono.

Por que Promises com XHR?

XHR funciona com callbacks ou eventos (onload, onerror), mas isso pode gerar código difícil de ler quando há várias requisições. Promises ajudam a escrever esse fluxo de forma mais clara, usando .then(), .catch() e .finally().

Ligação com os outros assuntos: o XHR clássico é a base, o fetch() substitui XHR em projetos modernos, mas o conceito de Promise é útil para entender fetch e async/await.

Transformando XHR em Promise

Uma Promise representa um resultado que ainda não chegou. No XHR, você já tem um momento em que a requisição termina: onload ou onerror. Com uma Promise, colocamos o sucesso em resolve() e o erro em reject(). 

function xhrPromise(method, url) {
  return new Promise(function (resolve, reject) {
    const xhr = new XMLHttpRequest();
    xhr.open(method, url, true);

    xhr.onload = function () {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(xhr.responseText);
      } else {
        reject(new Error("HTTP " + xhr.status));
      }
    };

    xhr.onerror = function () {
      reject(new Error("Falha de rede ou CORS"));
    };

    xhr.send();
  });
}

Agora, xhrPromise("GET", url) devolve uma Promise. Se a requisição for bem-sucedida, o próximo .then() recebe a resposta. Se der erro, o .catch() captura tudo.

Encadeando .then() e .catch()

xhrPromise("GET", "https://jsonplaceholder.typicode.com/posts/1")
  .then(function (responseText) {
    const post = JSON.parse(responseText);
    console.log(post);
    return xhrPromise("GET", "https://jsonplaceholder.typicode.com/users/" + post.userId);
  })
  .then(function (userText) {
    const usuario = JSON.parse(userText);
    console.log("Autor:", usuario.name);
  })
  .catch(function (erro) {
    console.error("Deu ruim:", erro.message);
  });

Primeiro você faz uma requisição. No .then(), você recebe a resposta e pode iniciar outra requisição. Como o segundo .then() recebe a Promise retornada pelo primeiro, ele espera a segunda requisição terminar.

Em outras palavras: cada .then() trata o próximo passo do fluxo.

Erros e tratamento único

Com Promises, você trata falhas em um só lugar usando .catch(). Isso evita duplicar callbacks de erro para cada requisição. 

xhrPromise("GET", "https://api.exemplo.com/dados")
  .then(function (texto) {
    return JSON.parse(texto);
  })
  .then(function (dados) {
    console.log(dados);
  })
  .catch(function (erro) {
    console.error("Erro no fluxo de requisições:", erro);
  })
  .finally(function () {
    console.log("Fluxo de requisição finalizado");
  });

.finally() roda independente do sucesso ou erro, ideal para liberar recursos ou habilitar botões após a requisição.

XHR + Promise vs Fetch

O fetch() já retorna uma Promise nativa. O exemplo abaixo mostra a mesma ideia: 

fetch("https://jsonplaceholder.typicode.com/posts/1")
  .then(function (response) {
    if (!response.ok) throw new Error("HTTP " + response.status);
    return response.json();
  })
  .then(function (post) {
    console.log(post);
  })
  .catch(function (erro) {
    console.error(erro);
  });

Usar Promises com XHR ajuda a entender o comportamento do Fetch e facilita a migração de código legado para APIs mais modernas.

Resumo

  • Promises tornam o fluxo assíncrono do XHR mais legível e encadeável.
  • resolve() indica sucesso; reject() indica erro.
  • .then() pode retornar outra Promise para criar sequências de chamadas.
  • .catch() centraliza o tratamento de falhas.
  • Fetch é o próximo passo natural, pois já trabalha com Promises nativas.
