Callbacks no jQuery

O que é callback e como usar success, error e complete nas requisições AJAX do jQuery.

O que é callback?

Callback é uma função passada como argumento para ser executada depois de um evento — no caso do AJAX, quando a requisição termina (com sucesso ou com falha). Como a requisição é assíncrona, você não pode fazer const dados = $.get(...) e usar na linha seguinte; você registra o que fazer quando a resposta chegar. 

// A requisição dispara e o script continua...
$.getJSON("/livros/1", function (livro) {
  // ← este callback roda só quando (e se) der certo
  console.log(livro.titulo);
});
console.log("Isso aparece antes da resposta");

Callbacks no $.ajax

O $.ajax aceita três callbacks principais no objeto de opções:

  • success — HTTP OK e resposta parseada com sucesso
  • error — falha HTTP, parse ou rede
  • complete — sempre no final, com sucesso ou erro
$.ajax({
  url: "https://api.exemplo.com/livros/1",
  method: "GET",
  dataType: "json",

  success: function (dados, textStatus, xhr) {
    console.log("Sucesso:", dados);
  },

  error: function (xhr, textStatus, errorThrown) {
    console.error("Falhou:", xhr.status, textStatus, errorThrown);
  },

  complete: function (xhr, textStatus) {
    console.log("Terminou (loading off)");
  }
});

Parâmetros do error

O callback de erro recebe três argumentos — úteis para debug:

  • xhr — objeto da requisição (status HTTP, headers, responseText)
  • textStatus — string como "error", "timeout", "parsererror"
  • errorThrown — mensagem de exceção ou status textual
Quando cada um dispara: success → status 2xx e corpo compatível com dataType. error → 4xx/5xx, JSON inválido com dataType: "json", timeout ou falha de rede/CORS.

Callbacks em $.get e $.post

Nos atalhos, o callback de sucesso vai como argumento — não há error embutido na assinatura simples: 

// 3º argumento = success
$.get("/livros", { pagina: 1 }, function (lista) {
  console.log(lista);
}, "json");

$.post("/livros", { titulo: "1984" }, function (resposta) {
  console.log(resposta);
}, "json");

Para tratar erro com atalhos, encadeie .fail() ou use $.ajax.

.done(), .fail() e .always()

$.ajax, $.get e $.getJSON retornam um objeto jqXHR (parecido com Promise). Você pode encadear callbacks: 

$.getJSON("https://api.exemplo.com/livros/1")
  .done(function (livro) {
    console.log("OK:", livro);
  })
  .fail(function (xhr, status, erro) {
    console.error("Erro:", status, erro);
  })
  .always(function () {
    console.log("Sempre executa no fim");
  });
  • .done() ≈ success
  • .fail() ≈ error
  • .always() ≈ complete

Use o estilo de objeto (success/error) ou o encadeado (.done/.fail) — não misture os dois no mesmo fluxo para não duplicar lógica.

complete / .always() — para quê?

Ideal para ações que devem rodar independente do resultado: esconder spinner, reabilitar botão, fechar modal de loading. 

$("#btn-buscar").prop("disabled", true);

$.getJSON("/livros")
  .done(function (lista) { renderizar(lista); })
  .fail(function () { mostrarErro("Não foi possível carregar"); })
  .always(function () {
    $("#btn-buscar").prop("disabled", false);
  });

Callback vs código síncrono

Erro comum: usar o resultado fora do callback. 

let livro;

$.getJSON("/livros/1", function (d) {
  livro = d;
});

console.log(livro); // undefined — ainda não chegou!

Toda lógica que depende da resposta deve ficar dentro do success, .done() ou em uma função chamada por eles.

Dentro do callback ou em função chamada por ele?

Você não precisa escrever tudo inline no .done(). Pode extrair para outra função — o importante é quando ela roda: só depois que os dados existem. 

function renderizarLivro(livro) {
  document.getElementById("titulo").textContent = livro.titulo;
}

$.getJSON("/livros/1", function (livro) {
  renderizarLivro(livro); // ✅ chamada depois que livro existe
});

renderizarLivro(livro);   // ❌ livro ainda não existe aqui

Passar callback como parâmetro — buscarLivro

Às vezes você encapsula a requisição e deixa quem chamou decidir o que fazer com o resultado. O 2º argumento (aoSucesso) é uma função que será executada quando a API responder. 

function buscarLivro(id, aoSucesso) {
  $.getJSON("/livros/" + id, function (livro) {
    aoSucesso(livro); // repassa o livro para quem pediu
  });
}

buscarLivro(1, function (livro) {
  preencherFormulario(livro);
  salvarNoCache(livro);
});

Linha a linha:

  1. buscarLivro(1, function...) — você pede o livro 1 e entrega uma função dizendo o que fazer depois.
  2. $.getJSON — dispara a requisição; o script não trava.
  3. Quando a API responde, o jQuery chama function (livro) { ... } de dentro de buscarLivro.
  4. aoSucesso(livro) — executa a função que você passou (preencherFormulario, salvarNoCache, etc.).
Ordem no tempo: primeiro registra o pedido → depois a API responde → só então roda preencherFormulario e salvarNoCache com dados reais. A função anônima que você passou em buscarLivro(1, function...) é o aoSucesso de dentro da função.

Por que usar esse padrão? A parte “buscar na API” fica em um só lugar; cada tela pode passar um aoSucesso diferente:

// Tela A — só preenche formulário
buscarLivro(1, function (livro) {
  preencherFormulario(livro);
});

// Tela B — só salva no cache
buscarLivro(1, function (livro) {
  salvarNoCache(livro);
});

Resumo

  • Callback — função chamada quando a requisição assíncrona termina.
  • success / .done() — resposta OK e parseada.
  • error / .fail() — HTTP, parse, rede ou timeout.
  • complete / .always() — limpeza final, ganhe ou perca.
