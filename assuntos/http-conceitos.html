Conceitos de HTTP

Method, status code, URL, URI, path e headers — fundamentos das requisições.

O que é HTTP?

HTTP (HyperText Transfer Protocol) é o protocolo que o navegador usa para comunicar com servidores. Toda vez que você faz uma requisição AJAX, XHR, Fetch ou jQuery, está usando HTTP por baixo dos panos.

HTTP é stateless: cada requisição é independente. O servidor não "lembra" das requisições anteriores, a menos que você use sessões ou tokens.

URL e URI

Às vezes as pessoas confundem URL e URI. Tecnicamente:

  • URI (Uniform Resource Identifier): identificador único de um recurso. Exemplo: /api/livros/42
  • URL (Uniform Resource Locator): URI completa com protocolo e domínio. Exemplo: https://api.exemplo.com/api/livros/42

Na prática: todo URL é uma URI, mas nem toda URI é um URL. Para seu PDI, o importante é saber que você está fazendo requisições para URLs.

Anatomia de uma URL

https://api.exemplo.com:8080/api/livros/42?ordenar=titulo&pagina=1#secao-reviews

|      |                    |   |                       |
|      |                    |   |                       └─ Fragment/Anchor
|      |                    |   └─ Path (URI)
|      |                    └─ Port (8080 é alternativo)
|      └─ Domain
└─ Protocol/Scheme
  • Protocol: https:// (ou http://)
  • Domain: api.exemplo.com
  • Port: :8080 (opcional; padrão é 80 para HTTP, 443 para HTTPS)
  • Path: /api/livros/42 (identifica o recurso)
  • Query String: ?ordenar=titulo&pagina=1 (parâmetros)
  • Fragment: #secao-reviews (não é enviado ao servidor)

HTTP Methods (Verbos HTTP)

O HTTP define "métodos" ou "verbos" que indicam a ação que você quer executar no servidor:

Method Descrição Exemplo
GET Buscar/ler dados (seguro, idempotente) GET /api/livros
POST Criar dados novos POST /api/livros
PUT Substituir um recurso completo (idempotente) PUT /api/livros/42
PATCH Atualizar parte de um recurso PATCH /api/livros/42
DELETE Deletar um recurso (idempotente) DELETE /api/livros/42

Idempotente significa que fazer a mesma requisição várias vezes tem o mesmo efeito que fazer uma vez (GET, PUT, DELETE são idempotentes; POST não).

HTTP Status Codes

Toda resposta HTTP tem um status code (número de 3 dígitos) que indica o resultado da requisição:

Código Categoria Exemplos
1xx Informacional 100 Continue
2xx Sucesso ✓ 200 OK, 201 Created, 204 No Content
3xx Redirecionamento 301 Moved Permanently, 304 Not Modified
4xx Erro do cliente 400 Bad Request, 401 Unauthorized, 404 Not Found
5xx Erro do servidor 500 Internal Server Error, 503 Service Unavailable

Verificando o status em JavaScript

// Com Fetch
fetch("https://api.exemplo.com/livros/999")
  .then(response => {
    console.log(response.status);      // Ex: 404
    console.log(response.statusText);  // Ex: "Not Found"
    console.log(response.ok);          // true se 200-299, false caso contrário
    
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    return response.json();
  })
  .catch(error => console.error(error));

// Com XHR
const xhr = new XMLHttpRequest();
xhr.open("GET", "https://api.exemplo.com/livros/999");
xhr.onload = function() {
  console.log(xhr.status);      // Ex: 404
  console.log(xhr.statusText);  // Ex: "Not Found"
  
  if (xhr.status === 200) {
    const dados = JSON.parse(xhr.responseText);
  }
};
xhr.send();

HTTP Headers

Headers são metadados que acompanham requisições e respostas. São pares chave: valor que comunicam informações extras.

Headers comuns de requisição:

Content-Type: application/json
Authorization: Bearer seu_token_aqui
Accept: application/json
User-Agent: Mozilla/5.0...

Headers comuns de resposta:

Content-Type: application/json
Content-Length: 1234
Cache-Control: max-age=3600
Set-Cookie: sessionId=abc123

Usando headers com Fetch:

fetch("https://api.exemplo.com/livros", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer seu_token_aqui"
  },
  body: JSON.stringify({ titulo: "JavaScript Moderno" })
});

Content-Type: tipos de dados

O header Content-Type indica o formato dos dados sendo enviados ou recebidos:

  • application/json — JSON (mais comum em APIs modernas)
  • application/x-www-form-urlencoded — Formulários HTML
  • text/html — HTML puro
  • text/plain — Texto simples
  • multipart/form-data — Upload de arquivos

Para seu PDI, você principalmente usará application/json ao trabalhar com a Faker API.

Resumo

  • HTTP é o protocolo das requisições na web;
  • URL identifica o recurso; path é a parte do recurso na URL;
  • Methods (GET, POST, PUT, DELETE) indicam a ação;
  • Status codes (200, 404, 500) indicam o resultado;
  • Headers transmitem metadados — Content-Type é crucial;
  • Sempre verificar response.ok antes de processar dados.
