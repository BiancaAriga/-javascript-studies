CORS

Quando ocorre o erro CORS e como resolver — entendendo a política same-origin.

O que é CORS?

CORS (Cross-Origin Resource Sharing) é um mecanismo de segurança do navegador que restringe requisições HTTP entre domínios diferentes.

Quando você faz uma requisição AJAX, Fetch ou jQuery para um domínio diferente do seu site, o navegador bloqueia a resposta se o servidor não permitir explicitamente.

Importante: CORS é uma política do navegador, não do JavaScript. Ferramentas como Postman ou cURL não sofrem com isso.

Same-Origin Policy

Antes de CORS, existia a Same-Origin Policy: "só podes fazer requisições para a mesma origem". Duas URLs têm a mesma origem se compartilham protocolo, domínio e porta.

URL Mesma origem? Motivo
https://exemplo.com ✓ SIM Mesmo domínio
https://api.exemplo.com ✗ NÃO Subdomínio diferente
http://exemplo.com ✗ NÃO Protocolo diferente (http vs https)
https://exemplo.com:8080 ✗ NÃO Porta diferente
https://outro.com ✗ NÃO Domínio diferente

O erro CORS

Quando você tenta fazer uma requisição para origem diferente sem permissão, o navegador exibe um erro assim no console: 

Access to XMLHttpRequest at 'https://api.outro.com/dados'
from origin 'https://seu-site.com' has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present on the requested resource.

Importante: A requisição foi feita, mas o navegador bloqueou a resposta. O servidor viu sua requisição, mas você não consegue ler a resposta.

Como CORS funciona

CORS usa headers HTTP para comunicar permissões:

1. Requisição (navegador manda):

GET /api/livros HTTP/1.1
Host: api.outro.com
Origin: https://seu-site.com

2. Resposta (servidor deve mandar):

HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://seu-site.com
Access-Control-Allow-Methods: GET, POST
Access-Control-Allow-Headers: Content-Type
Content-Type: application/json

[{ "titulo": "Clean Code", "autor": "Robert Martin" }]

Se o servidor NÃO enviar Access-Control-Allow-Origin, o navegador bloqueia o acesso aos dados.

Headers CORS importantes

Header Descrição Exemplo
Access-Control-Allow-Origin Qual origem pode acessar? * (qualquer) ou https://seu-site.com
Access-Control-Allow-Methods Quais métodos HTTP são permitidos? GET, POST, PUT, DELETE
Access-Control-Allow-Headers Quais headers podem ser enviados? Content-Type, Authorization
Access-Control-Max-Age Por quanto tempo cachear o preflight? 86400 (24 horas em segundos)

Preflight Request

Quando você faz uma requisição "complexa" (POST, PATCH, DELETE, ou com headers customizados), o navegador faz automaticamente um preflight request — uma requisição OPTIONS antes da requisição real: 

// Seu código:
fetch("https://api.outro.com/livros", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ titulo: "Clean Code" })
});

// O navegador faz automaticamente:
OPTIONS /livros HTTP/1.1
Host: api.outro.com
Origin: https://seu-site.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: content-type

// Servidor responde:
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://seu-site.com
Access-Control-Allow-Methods: POST
Access-Control-Allow-Headers: content-type

// DEPOIS a requisição real é feita...

Dica: Requisições GET simples NÃO fazem preflight — só requisições "complexas" (POST, PUT, DELETE, custom headers).

Soluções para CORS

1. Pedir ao servidor para habilitar CORS

Se você controla o servidor, configure os headers CORS. Exemplos:

Node.js / Express:

const express = require('express');
const cors = require('cors'); // npm install cors

const app = express();
app.use(cors()); // Permite CORS de qualquer origem

// Ou mais específico:
app.use(cors({
  origin: 'https://seu-site.com',
  methods: ['GET', 'POST']
}));

Python / Flask:

from flask_cors import CORS
from flask import Flask

app = Flask(__name__)
CORS(app)  # Permite CORS

2. Se NÃO controla o servidor: usar um proxy

Se o servidor não permite CORS e você não consegue mudar isso, crie um servidor proxy seu que:

  • Recebe requisições do seu site;
  • Passa adiante para o servidor remoto (não há bloqueio servidor-para-servidor);
  • Devolve a resposta com headers CORS.
// Ao invés de:
fetch("https://api.outro.com/dados")

// Use:
fetch("/api-proxy/dados")  // Seu próprio servidor passa adiante

3. JSONP (método antigo — menos recomendado)

JSONP (JSON with Padding) funciona contornando CORS usando <script> tags, que não sofrem restrições de origem. Raramente usado em APIs modernas.

Na prática: Faker API

A Faker API que você usa no seu PDI já habilita CORS — ela envia: 

Access-Control-Allow-Origin: *

Isso significa que qualquer site pode acessar — perfeito para aprender! 

// Isso funciona sem problemas:
fetch("https://fakerapi.it/api/v1/books")
  .then(r => r.json())
  .then(dados => console.log(dados));

Resumo

  • CORS é uma política de segurança do navegador;
  • Requisições cross-origin são bloqueadas a menos que o servidor permita;
  • O servidor comunica permissão via headers como Access-Control-Allow-Origin;
  • Requisições "complexas" (POST, custom headers) fazem preflight automaticamente;
  • Soluções: habilitar CORS no servidor, usar proxy, ou aceitar a restrição;
  • Faker API já permite CORS — sem problemas para seu PDI.
PDI Front — CORS. Você entenderá isso melhor quando conectar a APIs externas!
