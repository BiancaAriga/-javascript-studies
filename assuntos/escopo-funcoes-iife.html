Escopo de funções e IIFE

Escopo local, escopo global e como a IIFE ajuda a isolar variáveis no JavaScript.

O que é escopo?

Escopo define onde uma variável pode ser lida ou alterada. Em JavaScript, o motor procura o nome da variável do bloco mais interno para o mais externo — isso se chama cadeia de escopo (scope chain).

Regra prática: uma variável só existe onde foi declarada (com let, const ou var) e nos blocos filhos, salvo exceções como variáveis globais.

Escopo global

Variáveis declaradas fora de qualquer função ou bloco ficam no escopo global — em páginas web, isso costuma ser o objeto window no navegador. 

const appNome = "PDI Front";  // global

function mostrarApp() {
  console.log(appNome);       // acessa o global
}

mostrarApp(); // "PDI Front"

O problema: qualquer script na página pode ler ou sobrescrever o mesmo nome. Em projetos maiores, isso gera conflitos e bugs difíceis de rastrear.

Escopo local (de função)

Dentro de uma função, variáveis declaradas com let, const ou var pertencem ao escopo local daquela função. Fora dela, não existem. 

function contador() {
  let total = 0;        // local — só existe aqui
  total += 1;
  return total;
}

contador(); // 1
contador(); // 1 de novo (total é recriado a cada chamada)
// console.log(total); // Erro: total is not defined

Parâmetros também são locais: function soma(a, b) { ... } — a e b só vivem dentro de soma.

Escopo de bloco (let e const)

Além do escopo de função, let e const respeitam blocos { } (por exemplo, dentro de if ou for). 

if (true) {
  const temporario = 42;
}
// console.log(temporario); // Erro: temporario is not defined

var ignora o bloco e “sobe” para o escopo da função ou global — por isso hoje se prefere let e const.

O que é IIFE?

IIFE significa Immediately Invoked Function Expression: uma função criada e executada na mesma hora, sem precisar guardar referência a ela. 

(function () {
  const segredo = "só existe aqui dentro";
  console.log(segredo);
})();

// console.log(segredo); // Erro — variável isolada

Formas equivalentes comuns:

// Parênteses envolvendo a função
(function () { /* ... */ })();

// Ou o parêntese extra no início
(function () { /* ... */ }());

// Arrow function (ES6+)
(() => {
  const id = 1;
})();

Como a IIFE afeta o gerenciamento de escopo

  1. Isolamento: variáveis dentro da IIFE não vazam para o escopo global, reduzindo poluição do window e colisões de nomes.
  2. Encapsulamento: você expõe só o que quiser retornando um objeto ou atribuindo a uma variável global controlada (padrão módulo antigo), as variáveis internas são privadas caso não sejam retornadas.
  3. Estado privado: funções internas podem usar variáveis da IIFE sem que o resto do código as altere diretamente. 
const calculadora = (function () {
  let memoria = 0;  // "privada" — só acessível dentro da IIFE

  return {
    somar(n) {
      memoria += n;
      return memoria;
    },
    ler() {
      return memoria;
    },
    zerar() {
      memoria = 0;
    }
  };
})();

calculadora.somar(10); // 10
calculadora.somar(5);  // 15
// memoria; // Erro — não está no escopo global
Hoje em dia: em projetos modernos, módulos ES (import / export em arquivos .js) substituem boa parte do uso de IIFE. Mesmo assim, entender IIFE ajuda a ler código legado e a perceber por que isolar escopo importa.

Comparando: sem IIFE vs com IIFE

Sem IIFE (risco de conflito)

var contador = 0;  // global — outro arquivo pode sobrescrever

function incrementar() {
  contador++;
}

Com IIFE (nome protegido)

(function () {
  let contador = 0;

  window.incrementarSeguro = function () {
    contador++;
    return contador;
  };
})();

Aqui só incrementarSeguro fica global; contador permanece local.

Closure (fechamento): quando incrementarSeguro é criada dentro da IIFE, ela “lembra” o ambiente onde nasceu — inclusive a variável contador, mesmo depois que a IIFE já terminou de executar. Essa ligação entre função e variáveis do escopo externo é a closure: a função continua acessando contador sem expô-la no global. Por isso o padrão acima isola o estado e ainda permite usá-lo de fora, só pela API que você publicou.

Resumo

  • Global: acessível em todo o script; use com moderação.
  • Local (função/bloco): variável existe só onde foi declarada.
  • IIFE: função executada na hora; cria um “módulo” temporário e isola variáveis.
  • Objetivo: menos nomes no global, menos bugs por sobrescrita acidental.
