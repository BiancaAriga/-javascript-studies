Fetch API

Requisições HTTP com JavaScript nativo — sem jQuery e sem montar XHR manualmente.

O que é a Fetch API?

fetch() é uma função global do navegador (desde ~2015) para fazer requisições HTTP. Ela retorna uma Promise e substitui, na prática, o trio XHR + callbacks + bibliotecas para a maioria dos casos novos.

Evolução no seu PDI: XHR puro → jQuery ($.ajax) → Fetch (nativo). Na Etapa 3 da aplicação prática você refatora o app de livros trocando jQuery por fetch.

GET básico

fetch("https://api.exemplo.com/livros/1")
  .then(function (response) {
    return response.json();
  })
  .then(function (livro) {
    console.log(livro);
  })
  .catch(function (erro) {
    console.error("Falha:", erro);
  });

fetch(url) dispara um GET. O 1º .then recebe o objeto Response; o 2º recebe os dados já parseados.

O objeto Response

  • response.ok — true se status for 200–299
  • response.status — código HTTP (200, 404, 500…)
  • response.json() — lê o corpo como JSON (retorna Promise)
  • response.text() — lê o corpo como string
Atenção: fetch só vai para .catch() em falha de rede (sem conexão, CORS bloqueado). Em 404 ou 500, a Promise resolve normalmente — você precisa checar response.ok. 
fetch("https://api.exemplo.com/livros/999")
  .then(function (response) {
    if (!response.ok) {
      throw new Error("HTTP " + response.status);
    }
    return response.json();
  })
  .then(function (livro) {
    console.log(livro);
  })
  .catch(function (erro) {
    console.error(erro.message);
  });

POST com JSON

O 2º argumento de fetch é um objeto de opções — equivalente ao config do $.ajax: 

fetch("https://api.exemplo.com/livros", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    titulo: "Dom Casmurro",
    autor: "Machado de Assis"
  })
})
  .then(function (response) {
    if (!response.ok) throw new Error("HTTP " + response.status);
    return response.json();
  })
  .then(function (livroCriado) {
    console.log("Criado:", livroCriado);
  });
  • method — GET, POST, PUT, DELETE…
  • headers — cabeçalhos (como contentType no jQuery)
  • body — corpo da requisição (POST/PUT/PATCH)

Fetch vs jQuery — mesma ideia, sintaxe diferente

jQuery

$.getJSON("/livros/1", function (livro) {
  console.log(livro);
});

Fetch

fetch("/livros/1")
  .then(function (r) { return r.json(); })
  .then(function (livro) { console.log(livro); });

No Fetch você monta headers e body manualmente, mas não precisa instalar jQuery. O parse JSON é response.json() — parecido com dataType: "json".

async / await (visão rápida)

Com Fetch + Promises, dá para escrever código que parece síncrono. Você verá isso com mais detalhe no assunto async/await: 

async function carregarLivro(id) {
  const response = await fetch("https://api.exemplo.com/livros/" + id);

  if (!response.ok) {
    throw new Error("HTTP " + response.status);
  }

  const livro = await response.json();
  return livro;
}

Resumo

  • fetch(url, options) — HTTP nativo; retorna Promise.
  • Leia o corpo com response.json() ou response.text().
  • Verifique response.ok — 4xx/5xx não caem no catch sozinhos.
  • Substitui jQuery/XHR em projetos modernos sem dependência extra.
  • Próximo passo: Promises e XHR.
