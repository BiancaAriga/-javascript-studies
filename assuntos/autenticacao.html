Autenticação

Entenda como usar o header Authorization para autenticar requisições HTTP.

O que é o header Authorization?

O header Authorization é enviado em requisições HTTP para informar credenciais ao servidor. Ele é usado quando o servidor protege recursos e exige autenticação.

Basic Authentication

A autenticação básica envia usuário e senha codificados em Base64. O formato é Authorization: Basic base64(usuario:senha).

Base64 é uma forma de codificar dados em texto seguro usando 64 caracteres imprimíveis. No JavaScript, a função btoa() converte uma string em Base64. 

const usuario = 'ana';
const senha = '123456';
const token = btoa(`${usuario}:${senha}`);

fetch('https://api.exemplo.com/login', {
  headers: {
    'Authorization': `Basic ${token}`
  }
});

Bearer Token

O tipo mais comum em APIs REST modernas é o Bearer Token. Ele envia um token de acesso que o servidor valida.

Um JWT (JSON Web Token) é um token compacto e seguro que carrega informações em três partes: header, payload e assinatura. Ele é usado para provar a identidade do usuário e transmitir dados de autorização.

Diferente do Basic, que usa btoa(usuario:senha), o JWT não deve ser criado no cliente. O servidor gera o JWT depois de verificar o login, assina o token com um segredo e devolve ao cliente. O cliente apenas envia esse token no header Authorization: Bearer .... 

const token = 'seu.jwt.aqui';

fetch('https://api.exemplo.com/perfil', {
  headers: {
    'Authorization': `Bearer ${token}`
  }
});

Quando usar cada tipo

  • Basic: útil para autenticação simples ou em APIs legadas.
  • Bearer: recomendado para tokens e autenticação moderna.

Exemplo prático com Fetch

Veja como enviar o token no header e tratar a resposta. 

fetch('https://api.exemplo.com/dados', {
  method: 'GET',
  headers: {
    'Authorization': 'Bearer seu.jwt.aqui',
    'Content-Type': 'application/json'
  }
})
  .then(res => {
    if (!res.ok) throw new Error('Não autorizado');
    return res.json();
  })
  .then(data => console.log(data))
  .catch(err => console.error(err));

Boas práticas

  • Não guarde tokens sensíveis em localStorage se o app puder ser atacado por XSS.
  • XSS (Cross-Site Scripting) é um ataque onde código malicioso é injetado e executado no navegador de outro usuário (vítima do ataque).
  • Use HTTPS sempre que enviar headers de autenticação.
  • Evite expor credenciais em URLs ou código público.
