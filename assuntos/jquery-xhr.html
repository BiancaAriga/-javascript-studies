jQuery e abstração do XHR

Como o jQuery simplificou requisições HTTP em cima do XMLHttpRequest com $.ajax, $.get e $.post.

Por que o jQuery entrou em cena?

No início dos anos 2000, fazer AJAX com XHR puro era verboso: criar o objeto, configurar open e send, tratar readyState, parsear JSON manualmente e lidar com diferenças entre navegadores. O jQuery (lançado em 2006) unificou isso em poucas linhas e popularizou o padrão “buscar dados sem recarregar a página”.

Ideia central: por baixo dos panos, $.ajax ainda usa XMLHttpRequest (ou alternativas do navegador). O jQuery é uma camada de abstração — você declara o que quer; a biblioteca cuida dos detalhes repetitivos.

XHR puro vs jQuery (mesmo GET)

Com XMLHttpRequest

const xhr = new XMLHttpRequest();
xhr.open("GET", "https://api.exemplo.com/livros/1", true);

xhr.onload = function () {
  if (xhr.status >= 200 && xhr.status < 300) {
    const livro = JSON.parse(xhr.responseText);
    console.log(livro);
  }
};

xhr.onerror = function () {
  console.error("Erro na requisição");
};

xhr.send();

Com jQuery — $.ajax

$.ajax({
  url: "https://api.exemplo.com/livros/1",
  method: "GET",
  dataType: "json",
  success: function (livro) {
    console.log(livro);
  },
  error: function (xhr, status, erro) {
    console.error("Erro:", status, erro);
  }
});

Com dataType: "json", o jQuery já entrega o objeto parseado em success — não é preciso chamar JSON.parse no responseText.

$.ajax — método completo

É a função mais flexível: aceita qualquer verbo HTTP, headers, corpo, timeouts e callbacks. Use quando precisar de controle total. 

$.ajax({
  url: "https://api.exemplo.com/livros",
  method: "POST",
  contentType: "application/json",
  data: JSON.stringify({ titulo: "Dom Casmurro", autor: "Machado" }),
  dataType: "json",
  success: function (resposta) {
    console.log("Criado:", resposta);
  },
  error: function (xhr, status, errorThrown) {
    console.log("Status HTTP:", xhr.status);
    console.log("Detalhe:", errorThrown);
  }
});

Opções úteis no dia a dia:

  • url — endereço da API
  • method ou type — GET, POST, PUT, DELETE…
  • data — query string (GET) ou corpo (POST)
  • contentType — formato do que você envia no corpo (ex.: application/json)
  • dataType — formato que você espera receber: "json", "text", "html"
  • headers — objeto com cabeçalhos extras (ex.: Authorization)
  • beforeSend — hook antes de enviar (loading, token)

contentType vs dataType

A diferença está no sentido da informação: um diz o que você manda; o outro, o que você espera de volta.

  • contentType — cabeçalho HTTP Content-Type da requisição. Informa ao servidor como ler o corpo que você enviou. Usado sobretudo em POST, PUT e PATCH.
  • dataType — opção do jQuery para a resposta. Diz como a biblioteca deve tratar o corpo antes de chamar success (por exemplo, fazer parse de JSON).
Resumo: contentType = etiqueta da caixa que você despacha; dataType = formato da caixa que você espera receber. No XHR puro ou no fetch, você define Content-Type no header ao enviar e usa JSON.parse ou response.json() ao receber. 
$.ajax({
  url: "/livros",
  method: "POST",
  contentType: "application/json",  // o que EU envio
  data: JSON.stringify({ titulo: "Dom Casmurro" }),
  dataType: "json",                 // o que EU espero receber
  success: function (livroCriado) {
    console.log(livroCriado.id);    // já é objeto
  }
});

$.get — atalho para GET

Quando você só precisa buscar dados, $.get encurta o $.ajax: 

// Assinatura: $.get(url, data, success, dataType)

$.get("https://api.exemplo.com/livros", { pagina: 1 }, function (lista) {
  console.log(lista);
}, "json");

Equivalente resumido:

$.get("https://api.exemplo.com/livros/1", function (livro) {
  console.log(livro.titulo);
});

O jQuery monta a query string a partir do objeto data e trata a resposta conforme o dataType informado.

$.post — atalho para POST

Para enviar dados ao servidor (criar recurso, formulário, etc.): 

$.post(
  "https://api.exemplo.com/livros",
  { titulo: "1984", autor: "Orwell" },
  function (resposta) {
    console.log("Salvo:", resposta);
  },
  "json"
);

Por padrão, $.post envia como application/x-www-form-urlencoded. Para JSON puro, prefira $.ajax com contentType: "application/json" e data: JSON.stringify(...).

application/x-www-form-urlencoded em resumo: formato de formulário HTML — os campos viram uma string chave=valor&chave2=valor2 no corpo do POST (espaços viram +, caracteres especiais são codificados). É o mesmo padrão de um <form method="POST"> tradicional. Bom para campos simples; APIs REST modernas costumam esperar application/json. 
// $.post com o exemplo acima envia no corpo:
// titulo=1984&autor=Orwell

$.getJSON

Atalho ainda mais específico: GET esperando JSON. Muito usado em tutoriais e APIs públicas. 

$.getJSON("https://api.exemplo.com/livros/1", function (livro) {
  console.log(livro);
});

O que o jQuery melhorou em relação ao XHR?

  • Menos código boilerplate — sem gerenciar readyState manualmente
  • JSON automático — com dataType: "json" ou $.getJSON
  • Callbacks padronizados — success e error em um só lugar
  • Serialização de data — objetos viram query string ou corpo POST
  • Compatibilidade histórica — mesma API em navegadores antigos
Hoje: projetos novos costumam usar fetch ou axios sem adicionar jQuery só por AJAX. Mesmo assim, entender $.ajax ajuda a ler código legado e a ver a evolução: XHR → jQuery → Fetch/Promises.
