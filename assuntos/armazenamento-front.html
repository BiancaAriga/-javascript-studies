Armazenamento no front-end

Aprenda a usar Local Storage e Session Storage para guardar dados no navegador.

Por que usar armazenamento no navegador?

O armazenamento no front-end permite guardar dados entre páginas ou sessões sem precisar de servidor. É útil para manter preferências do usuário, formulários parcialmente preenchidos ou dados temporários.

Session Storage

O sessionStorage armazena dados apenas enquanto a aba ou janela do navegador estiver aberta. Quando a aba é fechada, os dados somem. 

sessionStorage.setItem('nome', 'Ana');
const nome = sessionStorage.getItem('nome');
console.log(nome); // 'Ana'
sessionStorage.removeItem('nome');
sessionStorage.clear();

O sessionStorage é limitado à mesma origem e não compartilha dados entre domínios. Mesmo entre abas do mesmo site, cada aba/janela tem seu próprio sessionStorage.

Use sessionStorage quando precisar de dados temporários que não devem persistir após o fim da sessão.

Local Storage

O localStorage persiste os dados mesmo depois de fechar e reabrir o navegador. Ele fica disponível para o mesmo domínio e não expira automaticamente. 

localStorage.setItem('tema', 'escuro');
const tema = localStorage.getItem('tema');
console.log(tema); // 'escuro'
localStorage.removeItem('tema');
localStorage.clear();

O localStorage mantém os dados até que você remova explicitamente com localStorage.removeItem() ou localStorage.clear(), ou até que o usuário/navegador limpe os dados.

Use localStorage para preferências do usuário, dados de interface ou qualquer informação que precise ficar salva.

Armazenando objetos com JSON

localStorage e sessionStorage só guardam strings. Para salvar objetos, converta com JSON.stringify e leia com JSON.parse. 

const livro = { titulo: 'JavaScript para Iniciantes', ano: 2024 };
localStorage.setItem('livro', JSON.stringify(livro));

const livroSalvo = JSON.parse(localStorage.getItem('livro'));
console.log(livroSalvo.titulo);

Comparação entre sessionStorage, localStorage e cookies

Veja quando usar cada tipo de armazenamento no front-end:

Armazenamento Duração Escopo Quando usar
sessionStorage Até fechar a aba/janela Mesmo domínio + mesma aba/janela Dados temporários da sessão atual
localStorage Persistente até ser removido Mesmo domínio Preferências e dados que devem persistir
Cookies Expira conforme atributo `max-age`/`expires` Mesmo domínio (ou subdomínios se permitido) Dados que o servidor precisa receber automaticamente

Cookies

Cookies são pequenos arquivos de texto que o navegador armazena e envia automaticamente ao servidor em cada requisição. Eles são usados para guardar preferências, sessões de usuário e informações que precisam ser lidas pelo servidor. 

document.cookie = 'tema=escuro; max-age=3600; path=/';
const cookies = document.cookie;
console.log(cookies);

Um cookie tem formato nome=valor e pode incluir atributos como max-age, expires, path e secure. 

document.cookie = 'usuario=Ana; max-age=86400; path=/; secure';

max-age define quanto tempo o cookie fica válido em segundos. No exemplo acima, o cookie expira após 86400 segundos (24 horas).

expires define uma data e hora exata de expiração. Ele funciona como alternativa a max-age. Por exemplo: expires=Tue, 19 Jan 2038 03:14:07 GMT.

path define o caminho do site onde o cookie está disponível. Com path=/, o cookie é enviado em requisições para todas as páginas do site.

secure só envia o cookie em conexões HTTPS. Use quando o cookie contiver dados sensíveis e você quiser evitar envio em conexões inseguras.

O cookie fica disponível para o mesmo domínio e para o caminho definido em path.

Se você quiser compartilhar cookies entre subdomínios, use o atributo domain, por exemplo domain=.example.com. Isso faz o cookie funcionar em example.com, app.example.com e blog.example.com.

Sem o atributo domain, o cookie é host-only e só vale para o host exato onde foi criado.
