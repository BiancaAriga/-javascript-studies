DevTools — aba Network

Inspecionar requisições HTTP e entender como o navegador carrega recursos.

O que é a aba Network?

A aba Network do DevTools mostra todas as requisições que o navegador faz ao carregar uma página. Isso inclui HTML, CSS, JavaScript, imagens, fontes e chamadas de API.

É uma ferramenta essencial para depurar problemas de rede, analisar desempenho e verificar erros de requisição.

Como abrir a aba Network

  • Chrome / Edge: Ctrl+Shift+I ou F12 e clique em "Network".
  • Firefox: Ctrl+Shift+E ou F12 e selecione "Network".

Após abrir, recarregue a página para ver todas as requisições feitas no carregamento inicial.

O que cada coluna significa

  • Name: nome do recurso ou endpoint.
  • Status: código HTTP retornado (200, 404, 500 etc.).
  • Type: tipo de recurso (document, script, xhr, fetch, image etc.).
  • Initiator: o que iniciou a requisição — HTML, script ou outro recurso.
  • Size: tamanho do recurso transferido.
  • Time: tempo total gasto na requisição.

Filtros úteis

Use os filtros para encontrar rapidamente requisições específicas:

  • All: todas as requisições.
  • XHR / Fetch: chamadas de API feitas por JavaScript.
  • JS: arquivos JavaScript.
  • CSS: arquivos de estilo.
  • Img: imagens.

O filtro XHR / Fetch é especialmente útil quando você quer depurar APIs e requisições AJAX.

Inspecionar uma requisição

Clique em uma linha para ver detalhes da requisição. As abas comuns são:

  • Headers: mostra a URL, método, status e cabeçalhos enviados e recebidos.
  • Preview / Response: mostra o corpo da resposta em formato legível.
  • Timing: divide o tempo gasto em DNS, conexão, envio, espera e recebimento.
  • Cookies: mostra cookies enviados e recebidos.

DNS é o sistema que traduz um nome de domínio, como api.exemplo.com, em um endereço IP que o navegador usa para conectar ao servidor. Sem DNS, só seria possível acessar o site usando números, não nomes fáceis de lembrar.

Esses detalhes ajudam a identificar se o erro está na URL, no método, no corpo da requisição, nos cabeçalhos ou no próprio servidor.

Erros comuns

  • 404 Not Found: recurso não existe ou URL está errada.
  • 401 / 403: problema de autorização ou autenticação.
  • 500: erro no servidor.
  • CORS: se a aba Network mostrar bloqueio no console, o servidor não autorizou a origem da requisição.

Verificar payload e headers

Em requisições POST, PUT, PATCH e DELETE, o DevTools mostra o corpo enviado pelo navegador. Isso é útil para garantir que o JSON ou formulário está correto.

Em Headers, preste atenção em:

  • Content-Type: tipo de dado enviado (application/json, application/x-www-form-urlencoded, multipart/form-data).
  • Authorization: token ou credenciais.
  • Accept: formatos aceitos de resposta.

Esses formatos significam:

  • application/json: corpo em JSON. É o mais comum para APIs modernas, com dados estruturados como objetos e arrays.
  • application/x-www-form-urlencoded: dados em pares chave=valor codificados na URL, como em formulários HTML simples.
  • multipart/form-data: usado para upload de arquivos e dados mistos, onde cada campo é enviado em uma parte separada.

Dicas para usar a aba Network

  • Marque Preserve log para manter as requisições ao navegar ou recarregar.
  • Use Disable cache para evitar respostas em cache enquanto depura.
  • Em APIs, filtre por XHR ou fetch para encontrar apenas chamadas de dados.
  • Compare os dados enviados e recebidos para encontrar inconsistências.

Resumo

  • A aba Network mostra todas as requisições e ajuda a depurar HTTP no navegador.
  • Verifique método, URL, status, headers, payload e resposta.
  • Filtros como XHR/Fetch facilitam a análise de APIs.
  • Timing e tamanho ajudam a identificar problemas de desempenho.
