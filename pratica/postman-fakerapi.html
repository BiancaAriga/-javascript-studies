Prática: coleção Postman com DummyJSON

Exercícios para criar, organizar e validar requisições HTTP sem escrever código no navegador.

Objetivos

  • Criar uma coleção e um ambiente no Postman.
  • Simular requisições GET para diferentes recursos.
  • Usar parâmetros de consulta, variáveis e scripts de teste.
  • Investigar respostas de sucesso e de erro.

Preparação

  1. Crie uma coleção chamada PDI — DummyJSON.
  2. Crie um ambiente chamado DummyJSON - estudo.
  3. Adicione a variável base_url com o valor https://dummyjson.com.
  4. Salve todas as requisições dentro da coleção.
Formato das respostas:

Nas listas, a API retorna um objeto com uma coleção (products, users ou posts), além de total, skip e limit.

Exercícios

1. Listar produtos

Crie uma requisição GET chamada Listar produtos:

{{base_url}}/products?limit=5&skip=0

2. Paginar e selecionar campos

Duplique a requisição anterior e altere os parâmetros para buscar dez produtos a partir do décimo item:

{{base_url}}/products?limit=10&skip=10

Depois, solicite apenas alguns campos e compare o tamanho das respostas:

{{base_url}}/products?limit=5&select=title,price,stock

3. Explorar outros recursos

Crie uma pasta Recursos e adicione uma requisição para cada URL:

GET {{base_url}}/users?limit=3
GET {{base_url}}/posts?limit=3
GET {{base_url}}/carts?limit=3
GET {{base_url}}/todos?limit=3

Para cada recurso, identifique o campo que funciona como identificador e anote o nome da coleção retornada.

4. Buscar e ordenar produtos

Use a busca por texto e compare o resultado com uma listagem ordenada por preço:

{{base_url}}/products/search?q=phone
{{base_url}}/products?sortBy=price&order=asc&limit=5

Depois, altere order para desc. O que mudou na ordem dos produtos?

5. Validar a resposta com um teste

Na aba Tests da requisição de produtos, escreva um teste que verifique o status HTTP e o formato básico da resposta:

pm.test("resposta HTTP bem-sucedida", function () {
    pm.response.to.have.status(200);
});

pm.test("resposta possui uma lista de dados", function () {
    const corpo = pm.response.json();
    pm.expect(corpo.products).to.be.an("array");
    pm.expect(corpo.products.length).to.be.above(0);
});

Execute a requisição e observe os resultados na aba Test Results.

6. Criar uma variável a partir da resposta

Na aba Tests, salve o identificador do primeiro produto em uma variável de coleção:

const corpo = pm.response.json();
pm.collectionVariables.set("primeiro_produto", corpo.products[0].id);

pm.test("primeiro produto possui identificador", function () {
    pm.expect(corpo.products[0].id).to.exist;
});

Depois, consulte o produto com {{base_url}}/products/{{primeiro_produto}}.

7. Investigar erros

Crie uma pasta Erros esperados e execute estas chamadas:

GET {{base_url}}/recurso-que-nao-existe
GET {{base_url}}/products/999999

Registre o status, o corpo da resposta e a mensagem de erro. Explique por que o Postman continua conseguindo enviar a requisição mesmo quando a API responde com erro.

Desafio final

Execute a coleção pelo Collection Runner e confira o resumo de testes aprovados e falhos.

Referência rápida

  • limit: quantidade máxima de registros solicitados.
  • skip: quantidade de registros ignorados antes do resultado.
  • select: campos que devem ser incluídos na resposta.
  • products: array de produtos retornados.
